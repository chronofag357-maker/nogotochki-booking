# Отчёт о публикации сервиса

Проект: «Ноготочки», учебный сервис записи. Проверка 08.10.2026.

## 1. Адрес и адресная строка

Адрес: https://nogotochki.xn----8sbkaa6ampdcbaci6g.xn--p1ai/
(читаемое имя: nogotochki.допдоход-онлайн.рф).
По домену открывается «Ноготочки — учебная запись», не заглушка хостинга.
HTTPS работает с действительным сертификатом; предупреждения безопасности
браузер не показал. Отдельный значок замка во встроенном браузере не проверялся.
HTTP перенаправляет на HTTPS.

## 2. Три сценария на публичном адресе

### Сценарий 1. Запись клиента

После выхода из предыдущего аккаунта зарегистрирован новый вымышленный клиент
«Клиент видеопроверки», video-client-0810@example.test. Использовалась обычная
учебная вкладка, не отдельное окно инкогнито. Телефон сервис не запрашивает.
Выбраны «Маникюр с гель-лаком», Анна Ковалева, 14.10.2026, 10:00.
В кабинете появилась строка:
«№2 · Маникюр с гель-лаком · Анна Ковалева · 2026-10-14 10:00–11:30 · 1800 ₽ · Подтверждена».
Регистрация, выбор свободного слота и подтверждение завершились сохранением записи.

### Сценарий 2. Админка под клиентом

Под этим клиентом открыт /admin вручную. Дословный текст:
«Доступ закрыт», «403: Доступ только администратору», «Вернуться в сервис».
Это HTML-ответ сервера с HTTP 403, а не только спрятанная кнопка интерфейса.
API админки также проверяет роль на сервере.

### Сценарий 3. Время клиента и администратора

У клиента запись №2: «2026-10-14 10:00–11:30».
В админке та же запись №2: «2026-10-14 10:00–11:30».
Совпали, разница 0 часов. В дополнительном сценарии администратор перенёс
именно №2 на «2026-10-15 10:00–11:30»; клиент увидел это же время и уведомление
«Запись №2 перенесена на 2026-10-15, 10:00. Мастер: Анна Ковалева».
Часовой пояс студии — Москва, явно указан у поля даты.

## 3. Настоящий вход через Яндекс

Зарегистрировано приложение «Ноготочки — учебный сервис». Разрешения: email
и стандартный профиль (имя, логин и пол объединены Яндексом в одном разрешении).
Телефон и дата рождения не запрашиваются. Использован собственный аккаунт
владельца, не чужие персональные данные. Приложение учебное, не заявлено
как прошедшее проверку Яндекса. Вход и повторный вход реально выполнены.

SQLite проверена на сервере через SSH, а не в терминале Coolify:
роль = client; длина password_hash = 0 (пустая строка); provider = yandex;
id = 2; число пользователей с provider=yandex = 1. Повторный вход привёл
в тот же кабинет, дубль не создан. integrity_check = ok, foreign_key_check пуст.
Пароль Яндекса и токены провайдера в нашей базе не сохраняются.
Используется authorization code + PKCE S256, state и cookie-привязка запроса.
Конфигурация вынесена за пределы репозитория; идентификаторы, секреты и пароли
в этот отчёт не включены.

## 4. Разбор поломки публикации

Проверка времени прошла; следующий разбор гипотетический, не реальный инцидент.

Что мог бы увидеть: у клиента запись 10:00, а у администратора тот же ID в 07:00,
при этом обе страницы загружаются без сообщения об ошибке.
Предположение о причине: разные способы преобразования времени. До изменения
кода надо сопоставить значение в SQLite, ответ API и две функции отображения;
одно лишь системное время сервера не доказывает причину.
Как исправлять после подтверждения: единый формат даты/времени и явно заданный
часовой пояс студии в обеих ветках, без неявной зависимости от часового пояса ОС.
Как убедиться: новая запись на 10:00, сверка клиента и админа по одному ID,
перезапуск сервиса и повторная сверка. Ожидается 10:00 в обоих местах.
Отличие от локальной среды: сервер и браузер находятся на разных машинах,
поэтому локальное совпадение часовых поясов может скрывать ошибку.

## 5. Персональные данные и инфраструктура

Режим учебный. Плашка на главной дословно:
«Учебный проект. Не вводите настоящие персональные данные. Услуги и записи тестовые, оплата не принимается.»
В базе учебный администратор, два вымышленных клиента на example.test и
собственный аккаунт владельца для обязательной проверки OAuth. Телефон не
собирается, платежей нет; реальные клиенты студии не приглашались.
Адрес используется для проверки и сдачи, не для рекламы действующей студии.
Публичная регистрация технически открыта: плашка не является запретом ввода
реальных данных, поэтому это ограничение учебного режима.

После защиты план: согласовать с владельцем отключение именно учебного
приложения, сделать нужную копию результата и удалить его учебную базу и
резервные копии после подтверждения. Дата ещё не согласована — автоматическое
удаление не настроено. Общий VPS и основной домен удалять нельзя: на них
работают другие проекты. Поддомен можно отключить отдельно.

Deployment отличается от инструкции курса: существующий VPS, Node + systemd
и Nginx вместо Coolify, чтобы не покупать новый тариф и не расходовать RAM
на дополнительную панель. SQLite лежит вне каталога кода. Повторное развёртывание
реально сохранило запись №1 и сессию. Dockerfile подготовлен, но сборка не
проверена; автоматический deployment из GitHub не настроен. Эти возможности
не выдаются за выполненные.
