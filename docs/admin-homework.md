# Админ-панель и тестирование — отчёт

Проект «Ноготочки», 08.10.2026. Проверки выполнены в браузере на локальном сервере с вымышленными пользователями.

## 1. Доступ клиента к админке
Под browser-client@example.test открыт /admin. Дословно на странице: «Доступ закрыт», «403: Доступ только администратору», «Вернуться в сервис». Административных данных на странице нет. Проверка роли выполняется в server/http.js до выдачи данных; независимый HTTP-тест получает 403 и на /api/admin/bookings. Скрытие панели на клиенте — дополнительное удобство, а не механизм защиты.

## 2. Конфликт одного слота
Первый клиент: browser-client@example.test на 127.0.0.1. Второй: browser-second@example.test на localhost. Host-only cookie изолированы; обе вкладки обращаются к одной базе. В ОБЕИХ сессиях до подтверждения загружено и выбрано: ламинирование бровей, Марина Орлова, 14.10.2026 11:00. Первый подтвердил: «Вы записаны! №2», «Ламинирование бровей, Марина Орлова», «2026-10-14, 11:00–12:00 · 1800 ₽». Второй подтвердил старый выбор: «409: Время недоступно. Выберите другой слот.» После повторной загрузки свободного времени список начинается с 12:00; 11:00 отсутствует. Создана одна запись, не две. BEGIN IMMEDIATE и SQLite-триггеры предотвращают пересечение; дополнительный параллельный HTTP-тест получает 201/409.

## 3. Отмена администратором
Во второй сессии выполнен выход клиента и вход учебного администратора. В панели выбрана запись №2 и отменена с причиной «Мастер заболел — учебная проверка». Ответ интерфейса: «Изменения записи №2 сохранены.» Затем в независимой клиентской сессии нажато «Обновить кабинет».

## 4. Результат у клиента
Запись №2 не исчезла: статус «Отменена», рядом «Причина: Мастер заболел — учебная проверка». Заголовок изменился с «Уведомления · 0 непрочитанных» на «Уведомления · 1 непрочитанных». Текст уведомления дословно: «Запись №2 отменена. Причина: Мастер заболел — учебная проверка». Клиент получает изменение из базы, а не из общей памяти вкладок. Собственные действия не создают лишнего уведомления. Чужое уведомление нельзя пометить прочитанным: API возвращает 404.

## 5. Вывод и границы проверки
Все три требуемых сценария проверены через UI. Обнаружена проблема отображения отказа: JSON-ответ /admin встроенный браузер первоначально показывал как заблокированную загрузку. Исправлено на понятную HTML-страницу при сохранении реального HTTP 403; повторный браузерный прогон показал приведённый выше текст. Автотесты дополнительно проверяют перенос с сохранением ID, освобождение старого интервала, отмену без удаления, обязательную причину, запрет изменения чужой записи и сохранение исторической цены после изменения каталога. Это не утверждение о полной готовности всех расширенных возможностей: редактор графиков/мастеров и реальный OAuth ещё требуют доработки.
